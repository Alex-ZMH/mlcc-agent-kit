# H0 engineering model and VASP adapter

This note records the small implementation boundary for P2/P3.  The current
model is a four-atom conventional-cell Ni fcc engineering fixture generated by
`ase.build.bulk("Ni", "fcc", cubic=True)`.  It is a connection test only:
`fixture=true` and `scientific_status=engineering_fixture_not_production` are
written to `model.json`, and no ceramic phase or dopant choice is implied.

For a force/relaxation smoke input, the builder can apply an explicit
engineering displacement and records it in `model.json` (for example,
`--displaced-atom-id 0 --displacement-angstrom 0.03`).  The default is zero;
no geometry perturbation is hidden in the fixture generator.

The fixture writer is:

```powershell
python scripts/h0/build_fixture.py --output workspace/models/ni-fcc-engineering/v001
```

The output directory contains `source.cif`, `model.extxyz`, `model.json`, and
`dopants.json`.  Atom IDs are integer values assigned once in the explicit ASE
model and persisted in both metadata and the extxyz atom array.  `model.json`
also records the lattice, fractional/cartesian coordinates, element order,
composition, source description, actual ASE/pymatgen versions, and the fact
that production material selection is still pending.  When an engineering
displacement is requested, `source.cif` remains the unperturbed Ni mother
cell while `model.extxyz` carries the displaced working geometry; the
perturbation and both coordinate sets are recorded in `model.json`.
`read_model_artifacts` requires the extxyz atom IDs, composition, cell,
periodicity, elements, and coordinates to agree with `model.json`; it does
not overwrite inconsistent extxyz IDs.

`prepare_vasp` accepts an explicit `VaspParameters` instance.  `ENCUT`,
`ISMEAR`, `SIGMA`, `EDIFF`, `EDIFFG`, `ISPIN`, initial `MAGMOM`, the k-point
mesh, and relaxation controls are written directly to `INCAR`/`KPOINTS`; the
adapter does not select scientific values implicitly.  `POSCAR.atom-map.json`
records source index, source atom ID, element, and POSCAR index after grouping
by the caller-provided `element_order`.  This makes the original atom order
recoverable after a VASP run.  `NBANDS`, `LWAVE`, `LCHARG`, `LREAL`, `ISTART`,
`ICHARG`, `ISYM`, and `LORBIT` are explicit `VaspParameters` fields; the
caller must provide them so single- and four-GPU tasks can share one method
record.  `POTCAR` is never generated or copied: the authorized remote site
must assemble it in the recorded element order.

`parse_vasp_outputs` requires real `vasprun.xml`, `OUTCAR`, and `CONTCAR` files.
It directly reads the selected pymatgen `Vasprun.ionic_steps[-1]` fields for
`forces`, `stress`, `e_fr_energy`, `e_0_energy`, and `e_wo_entrp`, plus
`final_structure`, `converged_electronic`, and `converged_ionic`.  OUTCAR is
used directly for per-atom magnetization and is never an energy/force/stress
fallback.  `parse_potcar_file=False` prevents local POTCAR lookup.  The XML
final structure is checked against CONTCAR in atom count, element order,
lattice, and periodic-equivalent coordinates before source atom IDs are
restored.  A static SCF has `ionic_converged=null` because no ionic stopping
criterion applies.  Process exit status is a scheduler/task concern and is
not treated as scientific convergence by this parser.

The canonical result units and convention are explicit:

* `e_fr_energy`: VASP free energy `TOTEN` at finite smearing, in eV;
* `e_wo_entrp`: VASP energy without entropy, in eV;
* `e_0_energy`: VASP energy extrapolated to sigma→0, in eV;
* forces: eV/Angstrom;
* stress in VASP's compression-positive convention: raw printed kBar × 0.1
  to GPa;
* tensile-positive stress: `-0.1 * raw VASP kBar`, in GPa;
* stress Voigt order: `xx, yy, zz, yz, xz, xy`.

Both full stress matrices and both Voigt vectors are retained.  For a metal
with finite smearing, force/stress derivative comparisons use the finite-
smearing `e_fr_energy` reference; the three energy labels are not silently
collapsed into one total.

The implementation deliberately contains no POTCAR redistribution, automatic
retry, engine fallback, content-addressed cache, synthetic missing values, or
implicit production-material selection.  The current parser tests are unit
tests with a stubbed pymatgen object and do not claim a real VASP parse.  A
real H0 closure still requires the
project Slurm adapter, authorized remote POTCAR, validated NVHPC MPI launch,
and actual VASP relax -> SCF files before P3 can be reported complete.
