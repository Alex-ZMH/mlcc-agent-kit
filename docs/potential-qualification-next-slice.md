已有 LAMMPS 链能保存和核对工程任务的模型、势身份、输入命令、Slurm 终态与原生输出，但还没有材料势的生产资格判定。下一项应直接服务选定生产实验：**一个明确材料/相与一个明确候选势的同几何 ABACUS—LAMMPS 能量差、力和完整应力对照**，输出该实验范围内的适用/不适用/证据不足结论。不得通过修改 fixture 标志，把 Ni 接线任务升级成生产结果。

本次审查范围仅为 `lammps.py`、`lammps_tasks.py`、已存 Ni 势说明和 job41/45/47 证据；未审查通用 MD 统计或聚合物移植函数，避免与另一执行任务重叠。未检索或选定新的陶瓷势，未代选 BaTiO3 相。高分子两分支保留，材料与工艺未确认。

## 4. 直接服务生产实验的最小实现

### 4.1 先确定一个候选势与一个实验

优先沿用已确认的无掺杂 CaZrO3/Pnma 材料选择；具体工况引用集成窗口确认的 study，不在代码中写死温度。首先落实候选势的真实文件、版本、许可、元素映射、支持的模型形式和适用域来源。当前本文不能给出“已选 CZO 合格势”的结论。

以“该单相母体小应变与局域位移响应能否由该候选势复现”为一个可收敛的首项实验范围。优先复用已有且合格的同方法 ABACUS 原生构型；不足部分再列预算。若缺陷任务先有合格参考，可直接选它的完整必要结构集，不为迁就通用模板另造 Ni 任务。

一个母体局部响应首批可限 **6 个几何**：参考、正/负体积扰动、正/负一个指定剪切扰动、一个明确局域位移。它只是该局部实验的首批数据，不是完整弹性张量、全局势资格或缺陷/铁电资格。扰动幅度、参考 DFT 误差预算、E/F/应力容差必须在结果前登记，按实际目标精度确定；不能由测试结果倒推门槛。若拟合或调整势，验收几何必须与拟合数据分开，不能用这 6 个点同时拟合并声称独立验证。

### 4.2 只补实际缺口

1. 在现有 LAMMPS 模块增加资格静态任务所需的完整压力张量原生输出与解析。记录六分量顺序、bar→GPa 转换、坐标基底及机械应力符号；按模型映射旋转整个张量。采用静态、无速度的参考，避免把有限温度动能压力混入 DFT 静态应力。历史仅标量压力的输出继续保留，不能补零变成张量。
2. 增加一个直接领域比较函数，输入显式配对的 ABACUS 与 LAMMPS 任务路径、参考几何及预登记标准。重读原生输出和模型，比较同几何、同组成相对能（各引擎分别减其同一参考结构）、逐原子力和应力。保留两引擎原始数据，**不相减裸总能后称精度，不混作同源训练标签**。跨组成比较须另具明确参考定义，不能套用同组成零点消去。
3. 在现有任务创建/解析路径增加一个明确的“候选势资格实验”用途，允许真实科学模型进行资格静态计算，结果仍不自动授予生产资格。保留原工程 fixture 路径；不得要求把真实材料伪装为 fixture。资格输出绑定候选势版本、参考任务、实验范围、误差和缺口，而非一个可任意改写的全局 true 标志。

不新增调度框架、势仓库服务、自动选势/回退、训练流水线或通用注册表。此时不扩展 NVT/NPT、聚合物统计或完整温度矩阵。生产 MD 的放行仅在所需资格证据成立后处理；静态局部资格也不自动放行 MD。

### 4.3 误差与验收内容

配对结果至少保存每个结构的参考/候选能量差及误差、逐元素力误差与最大分量误差、六分量应力误差、原子数/体积/映射、原生来源和资源。汇总量不能遮住单个结构的明显失配。明确能量/原子和总能量的分母，压力与应力的符号和基底；先确认 ABACUS 原生应力标定，不能用一个未资格参考验证另一个方法。

软件检查只补新增物理合同：原子映射错位、不同几何/参考方法、应力顺序/旋转/符号、缺分量和缺参考不能给出有效资格。真实验收只跑选定实验中缺失的任务，保留 job ID、原生终态、数值收敛、资源和完整误差。合格与否均可形成真实实验结论；程序失败或证据不足不判材料不合格。

## 5. 资源与停止条件

GPU 优先以实际候选势和本机可用构建为依据。[已有 native-help](../workspace/reports/lammps-system-v001/native-help.txt) 的 Installed packages 未列出 GPU/KOKKOS；帮助页通用 `-suffix`/`-kokkos` 选项不能证明已有 GPU 可执行能力，job41/45 只证实 CPU 路径。对支持 GPU 的选定模型，应先明确兼容的实际程序/包与站点配置，再通过 Slurm 执行；不把现有 CPU 成功升级成 GPU 成功，也不静默回退 CPU。尚未计划新构建安装；若所选生产任务需要 GPU 版本，应作为明确部署步骤处理。CPU Berry 仅用于明确预算的小兼容任务；本来不支持 GPU 的建模/科学后处理等仍可按明确预算在 v100 Slurm CPU 上执行。Berry GPU 故障由其专属任务处理，本文不干预。

没有候选势资源/许可、目标实验范围、合格参考或误差预算时，具体列出缺项；仍可实现明确的张量与比较函数，但不能提交无依据的生产任务或报资格通过。所有后续模型生成、数值测试、计算和科学后处理均走 v100/Slurm。文档建议不是新计算授权，本文没有提交任何作业。
